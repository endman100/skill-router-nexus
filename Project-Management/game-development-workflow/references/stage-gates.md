# 遊戲研發階段與 Gate 參考

## 目錄

1. 立項階段
2. 前期製作
3. 正式開發
4. 測試階段
5. 發布與持續研發
6. 產品型態調整
7. 名詞表

## 1. 立項階段

**目標**：證明市場機會、產品定位與執行方式值得投入。

**主要活動**：

- 市場、受眾、競品、平台與渠道研究。
- 定義核心幻想、核心玩法、差異化與商業模式。
- 評估技術、玩法、IP／系統架構、成本、時程與資金來源。

**關鍵產出**：立項 PPT、市場分析報告、概念說明、成本／回報模型、Pre-Demo（可選）。

**立項 Gate**：

- 目標受眾與需求假設可被驗證。
- 核心體驗有清楚的成功指標。
- 高風險技術有 PoC、替代方案或可接受的降級路徑。
- 資源、預算、時程與商業目標大致相容。
- 決策者明確做出 Go、Pivot 或 Stop 決定。

**PM 檢查**：資源是否到位、時程是否可行、核心體驗是否符合預期、技術風險是否已收斂。

**未通過路徑**：調整受眾、產品支柱、範圍或商業模式後重新驗證；無法收斂時停止立項。

## 2. 前期製作

**目標**：用最低合理成本證明遊戲「做得出來而且值得玩」。

**主要活動**：

- 組建核心團隊並設定專案節奏。
- 鎖定核心玩法、美術方向、技術方案與商業模式。
- 使用佔位素材快速製作玩法原型。
- 製作 First Playable 或 Vertical Slice，進行內部及目標玩家驗證。

**關鍵產出**：可玩 Demo、玩法原型、基礎美術風格、技術 PoC、初版 backlog、製作估算、專案里程碑。

**原型 Gate**：

- 核心玩法循環可在沒有大量內容的情況下被體驗與評估。
- 主要技術風險已由可運行版本驗證。
- Vertical Slice 能代表目標品質與跨職能管線。
- 玩家測試結果支持繼續投資，或已形成可執行的修正假設。
- 團隊能基於實測速度更新成本和時程預估。

**PM 檢查**：每次 Demo 都有驗證目標；Review 有決策與責任人；回饋已進入 backlog 或被明確拒絕。

**未通過路徑**：回到產品支柱或原型迭代；限制嘗試次數與投資上限，避免無限打磨。

## 3. 正式開發

**目標**：把已驗證的核心體驗擴展為功能與內容完整的產品。

**主要活動**：

- 建立並維護 GDD、TDD、內容清單、資源規劃與發版節奏。
- 策劃、程式、美術、音效、敘事與 QA 以可整合切片推進。
- 持續產生可玩的整合版本，控制範圍與技術債。
- 追蹤效能、穩定性、內容產能與關鍵體驗指標。

**關鍵產出**：GDD、Technical Design Document、功能清單、內容／資產清單、內測包、Alpha 版本。

**Alpha Gate**：

- 核心功能已完成，主要玩法可用。
- 主流程能從開始跑到預定結束。
- 關鍵資產與系統已整合，可進行系統性 QA。
- 已知缺陷、技術債與缺失內容有優先級及負責人。
- 新增範圍受到變更控制。

**PM 檢查**：功能完整度、重大缺陷修復效率、版本整合健康度、團隊依賴與伺服器穩定性。

**未通過路徑**：回到製作循環修復、減少範圍或延後非核心內容；避免用測試階段承擔未完成設計。

## 4. 測試階段

**目標**：消除阻斷問題，證明產品、平台與營運流程能穩定交付。

**主要活動**：

- 阻斷缺陷、流程、相容性、效能、網路與回歸測試。
- 內部 Beta、多輪封閉測試、限量測試或 Soft Launch。
- 蒐集可用性、留存、付費、難度與整體體驗回饋。
- 驗證伺服器容量、客服、事故處理、渠道與合規流程。

**關鍵產出**：測試計畫、缺陷清單、內測／限測包、效能與穩定性報告、玩家回饋報告、發布候選版。

**Release Gate**：

- 阻斷與高風險缺陷低於明定門檻。
- 主要平台、裝置、網路和存檔／帳號流程通過測試。
- 核心體驗與必要商業指標達標，或偏差已被正式接受。
- 伺服器、監控、客服、回滾與事故處理已演練。
- 商店素材、年齡分級、隱私、風險提示與渠道要求已完成。

**PM 檢查**：重大 Bug 是否有效收斂、留存／付費是否達標、測試安排與回饋回流、發布阻塞項是否有 owner。

**未通過路徑**：回到修復與 QA；必要時縮小發布範圍、延後發布或撤回候選版。

## 5. 發布與持續研發

**目標**：安全發布，並以版本、營運數據和社群回饋維持產品生命週期。

**主要活動**：

- 發布 Gold／正式包、公測或正式上線版本。
- 監控崩潰、效能、伺服器、經濟、留存、評價與客服事件。
- 單機產品提供修復補丁、DLC 或擴充包。
- 長線產品驗證技術與時間可行性後，進行玩法、內容和活動迭代。

**關鍵產出**：正式包、商店素材、隱私／風險文件、版本更新紀錄、活動配置、營運與社群回饋報告。

**版本 Gate**：

- 美術、音效、文字與程式資源已進入正確版本。
- 渠道、地區、法規及平台認證要求已滿足。
- 版本分支、建置、提審、回滾與熱修流程可追蹤。
- 活動與策劃配置已經測試驗證。
- 社群與營運訊號已轉為可排序的決策輸入。

**PM 檢查**：版本分支、提審材料、資源入版、渠道狀態、風險預警與社群反饋。

**回饋路徑**：新版本上線 → 數據／社群回饋 → 優先級判定 → 技術與時間可行性 → 製作 → 測試 → 下一版本。

## 6. 產品型態調整

- **單機買斷制**：強化內容完成度、平台認證、存檔與首日補丁；將 DLC 作為發布後分支。
- **長線網路遊戲**：加入伺服器容量、監控、客服、反作弊、經濟與活動配置 Gate。
- **F2P 手遊**：把 Soft Launch、留存、付費、廣告、裝置覆蓋與商店政策納入 Release Gate。
- **獨立／眾籌專案**：可用 Vertical Slice 進行募資；把 Early Access 設為有退出條件的選配路徑。
- **外部發行商專案**：把發行商審核、素材交付、里程碑付款與平台提審加入每個 Gate。

## 7. 名詞表

- **First Playable**：首次能完整體驗核心玩法循環的版本。
- **Vertical Slice**：以接近目標品質呈現一小段端到端遊戲體驗。
- **GDD**：Game Design Document，遊戲設計文件。
- **TDD**：此流程中指 Technical Design Document，技術設計文件。
- **Alpha**：核心功能與主要流程已可完整運行的版本。
- **Beta**：以穩定性、相容性、平衡與玩家體驗驗證為主的版本。
- **Gold**：準備交付、送審或正式發行的候選版本。
- **Early Access**：正式完成前對玩家開放，以取得資金與回饋的發布策略。
