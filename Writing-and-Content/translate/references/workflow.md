# 翻譯與精翻執行細節

## 完整來源與格式保護

先使用內建／已連接來源工具讀取完整正文。對公開文章才可使用 Jina Reader 等公開 extractor；不得把私人文件 URL、登入 token 或原文送到第三方 proxy。403、缺頁或 paywall 不代表可以用摘要代替。內嵌引用、腳註、圖說與表格都屬原文，不能遺漏。

Markdown 依區塊讀取；code fence、inline code、URL、檔案路徑及程式識別符預設不翻。JSON／YAML 翻使用者可見字串，不改 key、數字型別、schema 或佔位符。SRT／VTT 保留 cue ID、時間範圍、順序及語法，只翻字幕文字。HTML 保留 tag／attribute 結構。不可用整段正規表示式替換所有看似英文的片段。

Frontmatter 預設保留 key 與來源 metadata。只有使用者明確要求譯介稿／發布包裝時，才按約定另建 `sourceTitle`／`sourceUrl` 等欄位，不覆蓋既有同名資料。不得把 baoyu 舊工作流的預設重命名套到所有 YAML。

## 語境分析與術語

normal 用最小必要分析；refined 記下主題、段落關係、說話者、語氣、領域術語、實體、修辭、雙關和跨段指代。這些是工作用譯注，不是要附加到所有最終譯文的導讀。

共用術語表採明確使用者要求 > 指定 glossary > 語對偏好 > 一般偏好 > 內建表。英中、中日、英日表保留既有來源的術語；部分中文原條目是簡體，不表示繁中輸出可以直接照抄。先決定目標 locale，再為本次任務建立繁中／臺灣用語版本，例如依語境使用「代理程式」、「提示詞」、「樣板程式碼」；使用者詞彙表優先，不武斷改其專名。

不要機械反轉一對多的術語表。`Grounding`、`Embedding` 等多義詞按語境選擇；名字、產品與縮寫尊重原文或官方寫法。直接 EN↔JA 等語對可在所選模型支援時執行，不沿用舊 polisher 的人為語對限制，也不預設經中文轉譯。

## 長文與 token 預算

1. 建立區塊序列及數量；先鎖定全篇術語、角色和日文文體。
2. 以**實際 tokenizer**計算 prompt+context+source+預留 output 的總 token；保留 runtime margin。原有 4000／5000 words 設定只作拆分提示，不是服務上下文上限；中文尤其不能只用空白字數。
3. `scripts/chunk_text.py` 提供按空白區塊、fence 和 frontmatter 的保守無損切分。遇到超大單一區塊會報錯；由 Agent 按段落／句意再切，或解析表格／JSON 擷取欄位，不能破壞 code fence／JSON 後假稱已保留格式。
4. 無須子 Agent 或子 Skill Router。主 Agent 逐塊呼叫所選後端；只在既有服務容量允許時使用有界 batch。
5. 相鄰背景只供理解，不能重複加入輸出。混合語言先明確劃分來源；MiLMMT 的來源不能為 `auto`。
6. 按編號合併，檢查每個區塊出現一次。原文附帶 frontmatter 只保留一次。回查跨塊代詞、承接、術語、語體、重複譯注。
7. finish_reason 為 length、空白譯文、缺漏區塊或 malformed JSON 必須處理；必要时縮小該塊重試，不能靠截斷或摘要勉強通過。

## 審校、修訂與自然度

refined 先只記診斷，再修訂；normal 至少做準確性與格式檢查。對照原文的每一段與標題，檢查以下要點：

- 意義：肯定／否定、條件、因果、程度、時間、主體與客體、指代、語氣和諷刺。不補不存在的資訊。
- 完整性：句子、段落、註解、數字、貨幣、單位、日期、專名；段落數大幅減少只是警訊，仍要逐段核對。
- 中文：避免生硬被動、抽象名詞堆疊、多餘連接詞及從英文搬來的「是…的」句型；不為短句而強切每一行。
- 英文：冠詞、介詞搭配、主語與指代、資訊順序、過度名詞化及原語遷移。
- 日文：全文鎖定敬體或常體，檢查每塊末尾／總結，減少多餘主語、片假名與硬式連接。公告、郵件、FAQ 通常敬體；評論、技術分析通常常體，明確風格要求優先。
- 修辭：按意圖處理隱喻、雙關、ACG／網路語境；保留原聲音與情感，不憑猜測加文化解說。
- 指令：術語、長度、欄位、格式、字幕、佔位符和保護區是否實際滿足。字幕字數與音節數不是相同指標。

內部摘要可記錄診斷，不交付隱藏推理。一般不加說明；必要文化譯註只在合適的輸出契約內標示，不混入必須純譯文的 JSON value／字幕。

## 檔案與交付

預設回覆譯文；要求保存時使用新輸出目錄及 `translation.md` 或指定格式。若保留中間產物，使用本次專用目錄內的 `01-analysis.md`、`02-prompt.md`、`03-draft.md`、`04-critique.md`、`05-revision.md`、`chunks/`。這些是工作紀錄，不是新的 Skill。

預設成功後只清理本次建立的暫存資料，失敗時先保留可恢復資料並告知。不得刪除原文、既有譯稿、使用者 glossary、其他進程或工作目錄。只有檔案實際存在才提供路徑；只建立 request／chunk 不得報告翻譯完成。

## 來源整合

整合本專案原有 baoyu-translate（含重複安裝版）的三模式、preferences 與分塊流程、translate-polisher 的中英日審校、MiLMMT／Hy-MT2 的推論規則，以及 visa-doc-translate 的雙語文件處理。上述能力在本 Skill 直接執行，不保留舊 SKILL.md 入口或轉送 wrapper。
