# OpenAI Image Prompting

通过 Skill Router 路由后使用本 skill。将需求转为可检查的图片任务，保留用户指定的语言、文案、风格与品牌内容。

来源：[OpenAI Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)，核对日期：2026-09-10。本包提供简要方法提炼和原创操作模板，不是官方全文镜像。

## 1. 建立任务记录

从上下文提取下列字段。仅在缺项阻止任务时询问，否则采用合理假设并简短标明，不逐项发问。

| 字段 | 记录内容 |
|---|---|
| mode | prompt-only / generate / edit / critique |
| deliverable | 用途、文件类型、数量、比例 |
| input_map | 实际可访问的参考图路径或附件标识，以及各自用途 |
| required | 用户硬约束，编号 R1、R2…… |
| optional | 可自由设计的内容 |
| acceptance | 每项硬约束对应的检查方式 |

先查看参考图再描述其内容。用户只要提示词时交付文本；要求生成或编辑时，按宿主指令调用可用图片工具，必要时返回 Router 选择执行 skill。不要假设本 skill 自带模型或 API 权限。

## 2. 组织提示词

说明成品用途、主体、构图、可见材质与光线。人物补充取景、视线和动作；文字标出原文、位置、次数与排版。编辑时分开写修改项和保留项；多图明确编号与作用。参数独立于视觉描述。每轮修正一个可辨识问题，以实际结果检查改善。

使用下列原创模板，删除无关字段，不强迫简单需求使用长提示词：

```text
交付：{用途、画幅、数量}
画面：{主体正在做什么、环境、前后关系}
设计：{视觉媒介、色彩、材质、光源、观看角度}
排版：{信息层次、留白、必须出现的文字及位置}
参考图：{图号 → 使用内容}
本轮改动：{具体区域与预期变化；新图时省略}
保留要求：{不可改变的已确认内容；新图时省略}
验收目标：{用户最关心的可观察结果}
```

## 3. 按需加载

- 需要摄影、海报、漫画、图表、换装、合成或局部编辑模板时，读取 [场景模板](references/scenarios.md)，只使用匹配分支。
- 涉及模型、API 参数、透明输出或迁移时，读取 [参数与来源](references/models-and-source.md)。动态参数以当前官方文档和实际工具 schema 为准。
- 不把 API 字段塞进不支持该字段的工具调用。用户指定的模型与工具优先；不可用时说明情况，不声称已切换成功。

## 4. 审查、执行与有限修订

先检查 prompt 是否覆盖 required 编号，是否误改原文，参考图编号是否与实际输入顺序一致。无法访问的输入标记为缺失，不编造。

执行后检查两类证据：

- 文件：存在、能解码、尺寸与数量正确；透明需求检查 alpha 数据及边缘。
- 视觉：核对文字、身份、产品结构、编辑范围和图表关系。未检查项明确标记。

优先修复未通过的硬约束。未指定预算时默认最多追加两轮；记录输入、修改点与结果，达标即停。预算用尽仍有问题时交付可用部分并说明缺项。不要以提示词保证像素一致。

仅凭 prompt 不能证明成图通过。工具不可用时交付 prompt 并说明未生成；prompt-only 任务不要求生成验证。

## 5. 交付

输出最终 prompt 或实际图片链接。需要复用时附参考图映射、实际参数与检查结果；建议参数不能写成已执行参数。完成声明仍经过 Router 的 VERIFY 与 DELIVER 阶段。
