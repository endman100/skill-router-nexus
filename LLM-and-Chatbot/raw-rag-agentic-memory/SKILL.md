# Raw-RAG：以原始對話檢索作為 Agent 記憶強基線

本條目整理論文 **《Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought》**（發表日期：2026-10-22，arXiv:2610.30755）的核心方法與發現。本檔為外部研究簡易包裝，完整實作與實驗設定請查閱原始論文與官方 GitHub。

## 適用情境

- 設計或評估 LLM Agent 長期對話記憶架構時，建立未經摘要／圖譜轉換的原始歷史檢索（Raw-RAG）基線。
- 需要保留時間順序、說話者關係與推導路徑，避免預先事實抽取或記憶覆寫造成證據流失的長對話問答。
- 比較現有記憶系統、Raw-RAG 與混合方案在正確率、成本與延遲上的取捨。

## 方法步驟（Raw-RAG）

1. **保留原始對話紀錄**：直接保存帶有日期／時間與說話者標記的原始對話，不預先做 LLM 事實抽取、摘要、圖譜建構或記憶覆寫。
2. **切分與建立向量索引**：以 `256-token` 片段、`32-token` 重疊切分原始對話並建立密集向量索引；每個片段須映射回原始訊息範圍。
3. **兩階段檢索與重排**：以問題向量透過餘弦相似度取回前 `128` 個候選片段，再由 cross-encoder reranker 選出前 `15` 個片段交給 reader 模型。
4. **依任務調整上下文呈現**：部分基準會展開命中片段所屬的完整 turn（因此 15 段不等於固定 3,840 tokens）；例如 MEME 按來源時間順序呈現，MemoryAgentBench 則停用 turn 展開。

## 基準實驗重點

- 在 `LoCoMo`、`LongMemEval`、`MEME`、`MemoryAgentBench` 四個長對話基準共 7 種 benchmark-model 設定中，Raw-RAG 在所比較的記憶系統中有 **6 種排名第一**（排除 Full-context），領先最強比較系統 `0.13–5.53` 個百分點。
- **核心原因**：原文檢索對必要證據（含答案值、時間順序、關係與推導路徑）的覆蓋率較高；即使完整存取已轉換的記憶庫，仍與原始證據存在準確率落差。
- **消融觀察**：在 MemoryAgentBench 特定設定中，移除 reranker 下降 `3.92` 個百分點，改用 atomic-fact 變體下降 `19.62` 個百分點（此為特定基準設定結果，不可直接推論所有結構化記憶皆無用）。

## 教學範例（虛構情境）

假設長 session 累積 10,000 則訊息，預算歷經多次變更：`9/1` 定為 10 萬、`9/15` 改為 15 萬、`10/3` 提及設計費另計、`10/5` 更正為「15 萬含設計費」。
- 原始訊息保存 `session_id`、`message_id`、`time`、`speaker`、`text`，片段索引記錄片段 ID、來源訊息範圍、原文與向量。
- 當詢問「目前預算多少，含設計費嗎？」時，透過檢索與 rerank 找齊歷次變更片段，reader 模型即可依最新更正回答「15 萬含設計費」。
- 注意：保留原文不等於檢索必然完整（若漏檢 `10/5` 仍會答錯）；且歷史對話僅為證據，不得視為新的權限或操作授權。

## 限制與工程應用注意事項

- **論文實驗限制**：評估基於離線公開基準，尚未直接證明即時互動、多模態與實際生產營運環境的端到端表現；reader 模型能力會影響狀態重建品質；效率數據排除回答生成與評分階段，不能宣稱端到端全面更快。
- **工程與架構建議（屬於應用建議，非論文已證明或系統已實作功能）**：
  - 可採「穩定偏好／規則」與「原始歷史證據檢索」分工，摘要或記憶條目保留連回原始對話的來源索引。
  - 評估時應在相同模型與輸入 token 預算下，實測比較現行記憶、Raw-RAG 與混合方案（例如以「本機優先後改為 LinkingAI 優先」這類偏好更新作為驗收題）。
  - 當使用者要求刪除或遺忘特定資訊時，必須同步清理原始對話與向量索引。
